외부 LLM API 아님

시험성적서, 성분표, 기업 자료를 외부 모델 사업자에게 전송하지 않습니다.

왜 자체호스팅인가

  • 기업 업로드 문서와 정책 근거의 외부 전송을 줄입니다.
  • 공공·기업 데이터 경계를 설명하기 쉽습니다.
  • 모델, 프롬프트, 로그, 버전을 운영자가 통제할 수 있습니다.
  • RAG/Rule Engine 결과를 내부망에서 바로 근거 설명에 사용합니다.

왜 T4 ×2 Replica인가

  • AWQ 4-bit 8B급 모델을 T4 16GB에서 PoC하기 위한 현실적인 초기 후보입니다.
  • 1대만 두면 GPU 장애가 LLM 기능 전체 장애가 됩니다.
  • 2대 독립 Replica는 한 대 장애 시 다른 한 대가 요청을 계속 받습니다.
  • Tensor Parallel이 아니라 HA와 동시 처리량을 위한 수평 확장입니다.

주의할 점

  • Replica 수를 늘려도 단일 요청 생성속도가 그대로 2배 빨라지는 것은 아닙니다.
  • 긴 Context, 큰 출력 토큰, 높은 동시성은 KV cache와 VRAM을 압박합니다.
  • OCR은 기본적으로 CPU Worker에서 처리하고 T4 LLM과 상시 경쟁시키지 않습니다.
  • 피크 동시 추론 16건은 부하테스트로 검증해야 합니다.

정리: `자체호스팅 LLM · T4 ×2 Replica · Qwen3-8B-AWQ + vLLM`은 리움의 민감 문서와 정책 근거를 외부 LLM API로 보내지 않고, 사설망 안에서 LLM 답변을 생성하겠다는 구성입니다. T4 두 대는 하나의 큰 GPU처럼 묶는 구성이 아니라, 같은 모델 서버를 두 벌 띄우는 독립 Replica입니다. 따라서 장점은 HA와 동시 처리량이고, 한 요청 자체의 속도나 긴 Context 한계는 vLLM 튜닝, Replica 추가, 상위 GPU 검토로 별도 대응해야 합니다.
