NHN / NAVER 비교

NHN Cloud가 강한 부분

  • 현재 구조도가 NHN 기준으로 먼저 작성되어 설계 연속성이 높습니다.
  • 공공 T4 가격이 명확합니다.
  • 복수 AZ 기반 장애영역 설명이 상대적으로 명확합니다.
  • PostGIS, pgvector 외에 pgRouting, pgAudit까지 기능 폭을 설명하기 좋습니다.
  • T4 Replica를 늘려 동시 처리량 확장이 가능합니다.

NAVER Cloud가 강한 부분

  • 공공 T4와 Cloud DB for PostgreSQL 단가가 직접 공개되어 가격 근거가 명확합니다.
  • Cloud DB for PostgreSQL의 HA, Read Replica, PostGIS, pgvector 근거가 공공 문서에서 직접 확인됩니다.
  • 현재 월 계획비가 NHN보다 약 17.6만원 낮습니다.
  • T4 이후 L4, L40S 등으로 GPU를 단계적으로 상향할 수 있습니다.
  • 장기적인 Private LLM 확장성 평가에서 우세합니다.

주의할 점

1. 이 금액은 최종 견적서가 아님

공식 가격과 공개 자료를 기준으로 만든 예산 기준선입니다. 실제 계약, 할인, 약정, 공공 조달 조건에 따라 바뀔 수 있습니다.

2. NHN DB 비용은 Proxy 포함

NHN RDS for PostgreSQL 서비스와 HA 근거는 확인했지만, 정확 공공 단가가 별도 노출되지 않아 MariaDB 동급 사양 가격을 대용했습니다.

3. T4 성능은 PoC 필요

Qwen3-8B-AWQ + vLLM이 T4 ×2에서 목표 지연시간을 만족하는지는 실제 문서, Context 길이, 동시 요청으로 검증해야 합니다.

기본 비용에서 제외SI 구축비, 인건비, 교육비, 컨설팅비, 기술지원 계약, 타 리전 DR, 업무량 종속 SMS/메일, 지도 API 사용량
나중에 민감도 확인 필요GPU 추가, 로그 증가, 문서 저장량 증가, DB Read Replica 추가, DR 요구사항 확정
성능 검증 지표p95 latency, Queue 대기시간, tokens/s, TTFT, TPOT, OCR 처리시간, DB read 부하
보안 검증 지표WAF/DDoS 구성, 사설 Object Storage 접근, Bastion 접속통제, 감사로그 WORM 보관, DB 접근 경로

최종 정리

초기 권고안은 NHN과 NAVER 모두 T4 ×2, PostgreSQL HA, Read Replica, NKS 3환경으로 구축할 수 있습니다. 비용은 거의 같은 수준입니다. 장기 AI 확장성은 NAVER가 유리하고, 기존 설계 연속성과 장애영역 설명은 NHN이 유리합니다. 따라서 최종 선택은 미래 LLM 확장 가능성, 공공 DB 가격 근거, 운영팀이 선호하는 장애 대응 구조를 함께 보고 결정해야 합니다.
