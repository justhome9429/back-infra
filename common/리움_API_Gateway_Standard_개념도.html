무엇을 하는가

  • API별 경로와 호출 정책을 한곳에서 관리합니다.
  • API Key, JWT 연계, 기관별 허용 정책 같은 입구 통제를 둡니다.
  • Rate Limit으로 과도한 호출이 API Pod와 DB를 흔들지 않게 막습니다.
  • API 호출량과 실패율을 운영자가 추적하기 쉽게 만듭니다.

왜 ALB와 별도인가

  • ALB는 트래픽을 API Pod 쪽으로 분산하는 네트워크 계층입니다.
  • API Gateway는 “이 API를 누가 얼마나 호출해도 되는가”를 다룹니다.
  • WAF는 공격 차단, ALB는 분산, API Gateway는 API 정책 통제입니다.
  • 따라서 세 구성은 중복이 아니라 서로 다른 역할입니다.

리움에서의 위치

  • 외부 사용자는 직접 API Pod나 DB로 들어가지 않습니다.
  • 진입 순서는 DNS/DDoS → WAF → ALB → API Gateway → API Pod입니다.
  • SG-API는 8080 포트를 Gateway/ALB 내부 호출에만 열어 둡니다.
  • OCR·ETL·RAG 같은 장시간 작업은 API가 큐에 넣고 Worker가 처리합니다.

주의할 점

오해정리
API Gateway가 API 서버다아닙니다. 실제 로직은 NKS API Pod에서 실행됩니다.
ALB가 있으면 Gateway가 필요 없다ALB는 분산, Gateway는 인증·정책·제한을 담당합니다.
Gateway가 DB를 직접 본다아닙니다. DB 접근은 API/Worker Pod가 SG-DB 규칙으로 수행합니다.
장시간 작업도 Gateway가 처리한다아닙니다. API가 큐에 넣고 Worker가 비동기로 처리합니다.
