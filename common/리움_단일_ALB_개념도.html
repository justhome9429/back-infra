단일 ALB를 쓰는 이유

여기서 단일 ALB는 한 AZ에만 있는 장비 1대가 아니라, Production 인입점을 1식으로 두고 AZ-A/AZ-B Public Subnet에 걸쳐 배치하는 Multi-AZ ALB를 의미합니다.

왜 단일 ALB인가

  • ALB 자체가 AZ-A/AZ-B 대상에 분산하므로 AZ별 ALB를 따로 둘 필요가 적습니다.
  • WAF, 인증서, Listener, 보안그룹, 로그 기준이 하나로 모여 운영 실수가 줄어듭니다.
  • 리움은 대형 B2C가 아니라 업무형 B2G2B 플랫폼이라 진입점 복잡도를 낮추는 편이 유리합니다.
  • 비용도 ALB/인증서/로그/정책을 중복 구성하는 방식보다 단순합니다.

AZ별 ALB를 두면

  • DNS 가중치·Failover·Health Check 정책을 별도로 맞춰야 합니다.
  • Listener, 인증서, 보안그룹, WAF 연동이 중복됩니다.
  • 트래픽 편중이나 장애 전환 기준이 ALB 밖으로 흩어집니다.
  • 명확한 격리 요구가 없다면 운영 복잡도 대비 이득이 작습니다.

언제 ALB를 나누는가

  • 인터넷용/내부용 ALB 분리, 환경별 Dev·Val·Prod 분리, 보안 경계가 다른 도메인 분리, 리전 단위 DR이 필요할 때는 별도 ALB가 합리적입니다.
정리: 리움 구조도에서 단일 ALB는 Production 외부 인입 경로의 표준 진입점입니다. 실제 가용성은 ALB 1식 안에서 AZ-A/AZ-B 대상 그룹, Health Check, API Gateway/NKS Pod 이중화로 확보합니다. 따라서 이 구조는 비용 절감만을 위한 축소안이 아니라, 현재 리움 트래픽 규모와 운영 난이도에 맞춘 단순하고 검증하기 쉬운 구성입니다.
