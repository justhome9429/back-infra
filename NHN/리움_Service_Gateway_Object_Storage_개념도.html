Service Gateway — Object Storage 사설 연결

Service Gateway는 Private Subnet의 서버와 Pod가 Object Storage API에 접근할 때, NAT나 인터넷을 거치지 않고 NHN Cloud 내부 네트워크로 보내는 사설 접근 경로입니다.

인터넷 경로 아님

사용자 브라우저가 Service Gateway에 직접 붙는 구조가 아닙니다.

왜 필요한가

  • 문서 원본과 OCR 결과가 인터넷 구간을 경유하지 않게 합니다.
  • Private Subnet의 Pod가 Floating IP 없이 Object Storage에 접근할 수 있습니다.
  • Object Storage는 대용량 원문, WORM, 로그 아카이브 저장소라 사설 접근이 보안 설명에 유리합니다.

구성 시 확인

  • Object Storage용 Service Gateway를 생성합니다.
  • 격리 VPC에서 토큰 발급도 필요하면 Identity용 Gateway도 같이 둡니다.
  • URL 접근은 엔드포인트와 Gateway IP 매핑을 확인합니다.

Service Gateway와 Object Storage 역할 구분

구성요소역할리움에서의 의미
Service GatewayVPC 안에서 NHN Cloud 서비스로 가는 사설 통로문서 처리 Pod의 Object Storage 접근 경로
Object Storage오브젝트 단위 대용량 저장소원문, OCR 결과, 로그, WORM 보관
정리: 이 박스는 Object Storage가 App Tier 안에 있다는 뜻이 아닙니다. 저장소는 NHN Cloud의 관리형 Object Storage이고, Service Gateway는 Private Subnet의 Pod/Node가 그 저장소 API로 갈 때 쓰는 내부망 통로입니다. 리움의 문서 원본, OCR 결과, 감사 로그는 민감도가 높으므로 인터넷/NAT 경로보다 Service Gateway 사설 연결로 설명하는 편이 맞습니다.
