NAVER Object Storage · Private Endpoint 사설 접근

NAVER VPC 환경에서는 Object Storage 접근에 private endpoint 주소를 사용해, 문서 원본과 OCR 결과가 인터넷/NAT 경로로 우회하지 않게 설명할 수 있습니다.
Private Subnet · NKS

API / Worker Pod

업로드 원본, OCR 결과, 리포트 파일을 Object Storage API로 저장·조회합니다.

Private Endpoint

VPC 내부에서 사용하는 Object Storage 접근 주소

kr.object.private.ncloudstorage.com

Object Storage

문서 원본, OCR 결과, WORM/로그 아카이브, 리포트 파일 보관

NAT/인터넷 경로 아님

일반 외부 API 호출과 문서 저장소 접근 경로를 분리해 설명합니다.

왜 필요한가

  • 시험성적서와 성분표는 영업비밀 가능성이 있어 경로 설명이 중요합니다.
  • Private Subnet의 Pod가 Object Storage에 접근할 때 인터넷 우회로 보이지 않습니다.
  • 보안성 검토에서 “문서가 어디로 이동하는가”를 설명하기 쉽습니다.

NHN과 표현 차이

  • NHN 구조도는 Service Gateway라는 박스로 사설 경로를 표현했습니다.
  • NAVER 구조도는 Object Storage private endpoint 주소를 사용하는 방식으로 표현합니다.
  • 둘 다 목적은 Private Subnet에서 Object Storage로 사설 접근을 설명하는 것입니다.

주의할 점

  • 사용자 브라우저가 private endpoint에 직접 붙는 구조가 아닙니다.
  • API/Worker Pod가 인증된 권한으로 Object Storage API를 호출합니다.
  • 버킷 정책, 접근키, 로그 보존은 별도로 운영 통제해야 합니다.
