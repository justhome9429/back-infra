보안 그룹 (Security Group) 규칙
읽는 법: A ← B는 “B에서 A로 들어오는 요청만 허용”한다는 뜻입니다. SG는 각 서버/서비스 앞의 출입문 방화벽입니다.
SG허용 인바운드와 의미
SG-WAF
80, 443 ← DNS/DDoS Guard
사용자 웹 요청이 DDoS 보호를 지난 뒤 WAF에 도착합니다.
SG-ALB
80, 443 ← SG-WAF
WAF가 통과시킨 HTTP/HTTPS 요청만 ALB로 전달됩니다.
SG-API
8080 ← API Gateway / SG-ALB
API Pod는 공개 인터넷이 아니라 Gateway/ALB 내부 호출만 받습니다.
SG-Worker
인바운드 없음
외부가 Worker를 직접 호출하지 않고, Worker가 큐·DB·AI·Storage로 나갑니다.
SG-AI
8000/443 ← SG-Worker
Worker만 사설 LLM 엔드포인트를 호출합니다. 외부 LLM API가 아닙니다.
SG-MQ
5672 ← SG-API, SG-Worker
API가 작업을 넣고 Worker가 꺼내 처리하는 RabbitMQ 통로입니다.
SG-DB
5432 ← SG-API, SG-Worker, SG-Bastion
서비스 Pod와 운영 세션만 PostgreSQL에 접근하고 인터넷은 차단합니다.
SG-Bastion
관리자 세션 ← VPN / 전용선
관리자는 먼저 Bastion에 접속한 뒤 내부 DB·서버를 점검합니다.
핵심 설계 포인트
  • 3-Tier · Multi-AZ · Dev/Val/Prod 3환경(클러스터 분리)
  • NKS(Kubernetes) — Control Plane ×3(Dev/Val/Prod·CSP 관리) · API Pod HPA / Worker Pod KEDA · Cluster Autoscaler
  • DB Primary(AZ-A) → Standby(AZ-B) 동기 복제 + 자동 Failover
  • RabbitMQ quorum 3노드 — durable·ack·DLQ·retry·PV
  • Read Replica ×1(Prod) 포함 · Primary와 분리된 read 부하 처리 · 캐시(EasyCache)는 미도입(옵션)
  • Object Storage는 Private Endpoint로 사설 접근
  • DB 운영은 Secure Access / Bastion 경유 — SG-DB에 SG-Bastion 필수
  • DB 관리형 — HA·Failover·백업·패치를 CSP가 담당
  • PostgreSQL 채택 — PostGIS(공간)+pgvector(RAG 벡터·키워드)를 DB 하나로
  • LLM 자체호스팅 — NAVER T4 16GB ×2 독립 Replica (Qwen3-8B-AWQ+vLLM) · 외부 LLM API 미사용(S등급 전송 배제)
  • GPU 상향: NAVER T4→L4→L40S→H100 · 임베딩·OCR은 CPU Worker 우선
  • PgBouncer는 K8s Pod(별도 VM 없음) · Patroni·etcd 불필요
  • DR(타 리전 Warm Standby)은 기본 제외 — BIA 확정 후 추가
